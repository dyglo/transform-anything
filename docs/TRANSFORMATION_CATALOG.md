Single-image operations accept one PNG/JPEG/WebP and return one reusable image. Combine accepts 2–8 ordered PNG/JPEG/WebP objects and produces one PNG. Frame creates one PNG with padding, background, an optional border and rounded image corners. Horizontal/vertical combining supports gaps, start/center/end alignment, native sizes or an explicit common height/width with preserved aspect ratios. Optimize accepts JPEG/WebP only. Remove BG and annotations produce PNG at original size. Canvas quality cannot guarantee smaller output. JPEG fills alpha white. Planned formats do not enter the registry until an actual executor exists.

All operations use Object → Registry → Engine → Executor → New Object → Graph. Multi-input/output execution is real: the shared engine validates every input/output and commits whole results atomically. Contract tests cover one-to-many and many-to-many execution/storage; currently exposed image tools produce one output. PDF transformations remain planned; cloud extension types do not prove remote processing exists.

Composition limits: 2–8 unique sources, at most 40 megapixels across selected sources, and output at most 40 megapixels / 16,384px per side. Backgrounds are transparent or solid six-digit colors. A solid background also fills transparent source pixels. Draft previews use the actual executor and never enter history/storage; Apply creates the reusable output, Cancel discards the draft. Combine keeps its layout, selection and source order while adding images or selecting history within the same session.
